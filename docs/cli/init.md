# sdd init

Initializes a project with SDD Tool.

## Usage

```bash
sdd init [options]
```

## Options

| Option | Description |
|--------|-------------|
| `-f, --force` | Overwrite existing configuration (changed `.sdd/` files are backed up to `<file>.bak`, or `<file>.1.bak`… if one exists, and reported; delete backups after review and do not commit them — add `.sdd/**/*.bak` to `.gitignore`) |
| `--skip-git-setup` | Skip Git/CI-CD setup |
| `--auto-approve` | Auto-approve all settings |
| `--with-domains` | Also create the domain config file `.sdd/domains.yml` |
| `--no-skills` | Skip skill generation (`.claude/skills/` and `.agents/skills/`) |
| `--legacy-commands` | Additionally write the legacy Korean slash commands to `.claude/commands/sdd.*.md` |

## Generated Files

`sdd init` always generates files for both Claude Code and OpenAI Codex.

```
your-project/
├── .sdd/
│   ├── constitution.md     # Project constitution template
│   ├── specs/              # Feature specs directory
│   ├── changes/            # Change proposals directory
│   ├── archive/            # Completed changes archive
│   └── templates/          # Spec templates
│
├── AGENTS.md               # SDD guide inside <!-- sdd:begin --> … <!-- sdd:end -->
├── CLAUDE.md               # Imports the guide via `@AGENTS.md`
│
├── .claude/                # Claude Code
│   ├── skills/             # 30 sdd-* skills — English, kebab-case
│   │   └── sdd-start/SKILL.md ...
│   └── agents/             # sdd-spec-reviewer.md, sdd-implementer.md, sdd-impact-analyst.md
├── .agents/
│   └── skills/             # Codex: the same 30 sdd-* skills
│       ├── sdd-start/SKILL.md ...
│       └── sdd-watch/agents/openai.yaml   # manual-only skills
└── .codex/
    └── agents/             # Codex: sdd-spec-reviewer.toml, sdd-implementer.toml, sdd-impact-analyst.toml
```

`.claude/commands/` is not generated by default. Use `--legacy-commands` (below) if you want it.

Skills and subagents are tool-owned and regenerated in place on every run; only changed `.sdd/` files are backed up with `--force`.

## Skills

`sdd init` generates 30 English skills under `.claude/skills/sdd-*/SKILL.md`. Claude Code exposes each skill as a slash command named after the skill (e.g., `/sdd-start`, `/sdd-spec`). Skills include these frontmatter fields:

- **`context: fork`** — 7 analysis/domain skills run in a forked context (`sdd-analyze`, `sdd-impact`, `sdd-report`, `sdd-research`, `sdd-reverse`, `sdd-search`, `sdd-sync`)
- **`disable-model-invocation: true`** — 5 utility skills that only you can invoke (`sdd-chat`, `sdd-cicd`, `sdd-guide`, `sdd-migrate`, `sdd-watch`)
- **`argument-hint`** — skills that take arguments
- **`allowed-tools`** — least-privilege patterns per skill (e.g., `Bash(sdd validate*)`)

To opt out of skill generation:

```bash
sdd init --no-skills        # Skip .claude/skills/ and .agents/skills/ entirely
```

## Codex Support

The same 30 skill definitions are written for Codex to `.agents/skills/sdd-*/SKILL.md`:

- Frontmatter contains only `name` and `description` (the Claude-only fields above are dropped).
- References to other skills use Codex notation: `$sdd-plan` instead of `/sdd-plan`.
- The 5 manual-only skills also get `agents/openai.yaml` with `policy.allow_implicit_invocation: false`, so Codex runs them only when you invoke them explicitly.

In Codex, invoke a skill with `$sdd-spec auth/login` or pick it from `/skills`. Codex also selects skills implicitly when a request matches their description.

## Subagents

Three subagents are written for both tools — `.claude/agents/<name>.md` (frontmatter `name`, `description`, `tools`, `model: inherit`) and `.codex/agents/<name>.toml` (`name`, `description`, `developer_instructions`):

| Subagent | Role | Claude Code tools |
|----------|------|-------------------|
| `sdd-spec-reviewer` | Read-only spec review (RFC 2119, GIVEN-WHEN-THEN, constitution); runs `sdd validate` / `sdd quality` and reports issues | `Read, Grep, Glob, Bash` |
| `sdd-implementer` | Implements `tasks.md` items test-first, runs the project's tests, keeps changes scoped to the spec | `Read, Grep, Glob, Bash, Edit, Write` |
| `sdd-impact-analyst` | Read-only impact analysis with `sdd impact` before a spec change | `Read, Grep, Glob, Bash` |

Delegate by name, e.g. "Have sdd-spec-reviewer review the auth/login spec".

::: warning Read-only is enforced by instructions
The read-only agents need a shell to run `sdd` commands. In Claude Code they get no `Edit`/`Write` tools, but `Bash` could still change files; in Codex the sandbox cannot be restricted per agent. Their read-only behaviour therefore relies on their instructions, not on a hard permission boundary.
:::

## AGENTS.md Block

The SDD workflow guide is written into the project-root `AGENTS.md`, which Codex reads directly:

- If `AGENTS.md` does not exist, it is created with only the block.
- If it exists, only the `<!-- sdd:begin -->` … `<!-- sdd:end -->` block is replaced, or the block is appended. Content outside the block and CRLF line endings are preserved.
- If the markers are unbalanced (e.g. a begin without an end), `sdd init` fails before writing anything.
- If a root `AGENTS.override.md` exists, `sdd init` warns: Codex reads it instead of `AGENTS.md`, so the SDD block would be hidden.
- `.sdd/AGENTS.md` is no longer generated. An existing one is left untouched and reported as no longer generated.

## CLAUDE.md Import

Claude Code does not read `AGENTS.md` when a `CLAUDE.md` exists, so `sdd init` also ensures `CLAUDE.md` imports it:

- If `CLAUDE.md` does not exist, it is created with a short header and the line `@AGENTS.md`.
- If only `.claude/CLAUDE.md` exists, `@../AGENTS.md` is added there instead.
- If it exists without that import, the line is appended. Existing content is never overwritten.
- An old `@.sdd/AGENTS.md` import line is replaced in place with the new import.
- Running `sdd init` again does not add the line twice.

## Legacy Commands

Claude Code merges custom commands into skills, so commands are no longer generated by default. If you still want the old Korean dot-notation slash commands (`/sdd.start`, ...) in `.claude/commands/sdd.*.md`, add `--legacy-commands`:

```bash
sdd init --legacy-commands  # Also write .claude/commands/sdd.*.md (legacy)
```

## Git Workflow Setup

After initialization, the tool analyzes your project structure and suggests Git workflow settings:

1. **Git Hooks Installation**: Automatic spec validation on commit/push
2. **Commit Template Installation**: Consistent commit message format
3. **GitHub Actions Setup**: Automatic validation and labeling on PRs

Each setting is executed **after user approval**.

### Auto-Approve (for CI/Scripts)

```bash
sdd init --auto-approve
```

All settings are applied automatically without prompts.

### Skip Git Setup

```bash
sdd init --skip-git-setup
```

Initializes only the SDD structure, skipping Git/CI-CD setup.

### Overwrite Existing Configuration

```bash
sdd init --force
```

## After Initialization

1. Run Claude Code (`claude`) or Codex (`codex`)
2. Start the workflow: `/sdd-start` (Codex: `$sdd-start`)
